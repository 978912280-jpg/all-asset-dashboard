## 2026-11-24 · 台账记录被整份覆盖（008163 卖出记录丢失）

**现象**：用户在后台登记了 008163 清仓卖出（13,339.91 份 @ 1.1254），随后一次代码提交后，`data/holdings.json` 里的 `trade_ledger` 变空，传统已实现从 +¥823 变 0，用户持仓数据也回退到旧版本。

**根因**：提交代码时 `data/holdings.json` 与远端同时被修改（用户刚在网页保存过）。解决 rebase 冲突时用了 `git checkout --theirs data/holdings.json`，而 rebase 过程中 `--theirs` 指的是**正在被应用的本地提交**，不是远端最新数据 → 整份写回了旧持仓/旧台账，把用户最新保存记录冲掉。

**规则（必须遵守）**
1. `data/*.json`（尤其 `holdings.json`、`crypto_cost.json`）冲突时，**禁止** `git checkout --ours/--theirs` 整份取一侧，禁止整份重写。
2. 正确处理：先 `git show origin/main:data/holdings.json` 读取远端最新内容，然后只做**字段级最小修改**（python 读 json → 改指定字段 → 写回），最后逐项核对：`traditional` 的 id 列表、`trade_ledger` 条数与每条 id/shares、`cash_accounts` 各账户金额。
3. 涉及代码改动又碰到数据文件冲突时，代码改动照常提交，数据文件按上一条在远端版本上重放，不能顺带回滚数据。
4. 页面版本号以代码为准（`scripts/build.py` 的 `PAGE_VERSION`、`index.html`/`admin.html` 的 `data-page-version`），不要相信 `holdings.json` 里可能很旧的 `meta.version`。

**已有的兜底**
- 后台读取：优先走 GitHub Contents API 读最新 `holdings.json`，失败才回退 Pages 文件，并在顶部黄字提示「可能载入旧缓存」。
- 保存前核对：提交前用 Token 读远端台账，若远端存在本地缺失的记录，弹窗确认，避免旧缓存覆盖。
- 构建备份：`daily.yml` 每次构建前把 `holdings.json` 复制为 `data/holdings_backup.json` 一并提交，日志打印「传统 N 个标的 / 台账 M 条」。

## 2026-11-24 · 台账数字输入小数点输不进去

**现象**：在「传统交易台账」卖出台账里输入 `1.` 或 `2.5`，小数点被吞掉，只能填整数。

**根因**：`input` 事件里每敲一个字符就 `renderLedger()` 全量重绘，值经 `Number()` 回填（`Number("1.") === 1`），小数点当场丢失。

**规则**：输入过程中的数字字段保留原始文本，**不在 input 时重建 DOM**；仅在 `blur`/`change` 时归一化，保存前统一转数字。

## 2026-11-24 · 已登记卖出记录没有「确定」入口 / 不显示记录

**现象**：填完卖出信息后找不到确认按钮，点页面的「保存并计算」后也看不到这笔记录。

**根因**：台账只有内存态、没有单笔确认；缺字段（未选标的、成本价为 0）的行会被构建静默跳过。

**规则**：表单类录入必须有显式的单笔确认与校验反馈（缺什么直接提示），未确认的行不计入并明确标注；已确认记录以只读记录行展示，编辑后再确认。

## 2026-11-24 · 清仓删标的后已实现盈亏算错

**现象**：把清仓标的从持仓表删除后，该笔卖出的已实现盈亏变成「卖出金额全额」或直接消失。

**根因**：已实现计算只从当前持仓取成本价；标的一删，成本价取到 0。

**规则**：确认登记时把 `cost_price`/`currency`/`name` 快照写进台账记录；计算与构建都「持仓成本优先，取不到用台账快照」；已删除标的仍要保留在该行下拉选项里（标记「已清仓」），否则保存时会被改成第一个标的。
